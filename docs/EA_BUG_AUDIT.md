# EA Bug Audit — 2026-10-02

Deep correctness audit of the implemented EA tree requested by the owner
("check in depth to make sure we do not have any bug"), and **re-run in depth on
the same day at the owner's second request** ("check again in depth"). The first
pass found 15 defects (table below); the second pass found 3 more (#16–#18) and
dismissed 5 candidate reports as false positives, with reasons.

Scope: `MQL5_Master/` — the shared engine (`Include/EACore.mqh`, `EASignals.mqh`,
`EATrade.mqh`, `EACommon.mqh`), the 65 strategy EAs generated by
`scripts/gen_additional_eas.py`, and the 13 legacy §1 EAs that live beside them.

Method: no MQL5 compiler exists in this environment, so the audit combined
(a) purpose-built static checkers (structure/braces, include resolution, symbol
resolution, `cfg/ctx/plan` field existence, call arity, duplicate definitions,
declared-before-use, dead config, magic uniqueness), (b) a line-by-line review of
the engine's hot path (entry gate, sizing, execution, exits, day/rollover
accounting), and (c) the repository's own contract checker
(`scripts/check_mql5_source.py`), which was extended so every defect class found
here is now caught automatically.

Every defect below was reproduced from the sources, fixed at the source of truth
(`scripts/gen_additional_eas.py` for generated EAs, the engine `.mqh` files for
the shared logic), regenerated, and re-verified.

## Second pass — 2026-10-02 (second in-depth request)

Same scope and method as above, with the emphasis on the classes the owner
named: compile blockers, include/path errors, **wrong bar indexing**, dead
config and double bookkeeping. All three defects were fixed at the source of
truth and the whole 65-EA set was regenerated and re-verified.

| # | Severity | Where | Defect | Fix |
|---|---|---|---|---|
| 16 | **High (signal timing, all 65 EAs)** | shared engine `EASignals.mqh`, 11 signal functions | `EA_Rates(sym, tf, start, count, r)` returns a series-indexed array in which **`r[0]` is the bar at `start`** (`ArraySetAsSeries` + `CopyRates`). Eleven signal functions fetched with `start=1` (so `r[0]` = last closed bar) and then treated `r[1]`, `r[d]` or `r[i]` as the trigger bar → every sweep/reclaim, ORB, EMA-pullback, Bollinger fade, break-retest, momentum-burst, NR4, pin/engulfing, order-block, FVG and z-score pattern was evaluated **one bar late** (and `out.barsAgo` was off by one). | The eleven sites now fetch from bar `0` (L336 `SigSweepReclaim`, L473 `SigORB`, L618 `SigEmaPullback`, L690 `SigRangeFade`, L821 `SigBreakRetest`, L948 `SigMomentumBurst`, L1028 `SigInsideBarBreakout`, L1125 `SigTwoBarReversal`, L1219 `SigOrderBlockRetest`, L1291 `SigFvgRetest`, L1346 `SigZScoreFade`) and the convention comment above `EA_Rates` states the rule: with `start=0`, `r[0]` = forming bar, `r[1]` = last closed. Deliberately unchanged — they loop from index 0 over a time-filtered window, so `start` only shifts the window and the trigger bar is the last closed one by construction: `SigRangeForDay` L187, `SigDonchian` L233, `SigVwapFade` L868, `SigAsianBreakout` L992, `SigGridArm` L1100, `SigFractals` L1388, `EATrade.mqh` L1055. |
| 17 | **High (dead strategy)** | `EA_studyarena_round10_gemini_3_1_pro_preview_high_reasoning.mq5` (tracker #63 family) | The liquidity-sweep test seeded its range from the sweep bar itself: `hi = r[0].high` followed by `sweptHigh = (r[0].high > hi + …)` and the mirror for lows. Both conditions are mathematically unsatisfiable, so `BuildPlan` could never return a plan — the EA could compile, initialise and then never trade. | Generator spec fixed: the local 4-hour extreme now excludes the current bar (`hi = r[1].high`, loop `i = 2 … InpSwingBars`), leaving the sweep test `r[0]` vs the *prior* range. A tree-wide detector for "extreme seeded from the same index it is compared against" now reports 0. |
| 18 | **Medium (dead config)** | 60 of the 65 generated EAs | The shared header emits a standard input block for every EA, but 47 EAs never wired `InpMaxSpreadPoints`, `InpDailyLossPct`, `InpTotalDdPct` and `InpProfitTargetPct` (173 declarations), 22 declared a duplicate `InpRiskPct` while `Configure()` used a strategy-specific risk input, 6 declared an unused `InpMaxTradesPerDay`, and 32 spec-specific inputs were likewise unreferenced (e.g. `InpTimeStopBars`, `InpRunnerTrailAtrH1`, `InpChandelierMult`, `InpVolLowPct/HighPct` in files that hardcode the value). Any user setting those knobs was silently ignored. | 237 declarations removed at the generator: `render()` now drops every `input` whose identifier never appears in `Configure()`/`BuildPlan()`/`extra` (comments excluded). `main()` re-scans the rendered text and fails with `DEAD INPUT <file>: <names>` if one survives — a built-in positive control. No behaviour changed (the removed inputs were inert); the 65 EAs still set `cfg.riskPct`, `cfg.magic`, `cfg.symbols` from live inputs. |

### Candidate reports dismissed as false positives (not "fixed")

| Report | Verdict |
|---|---|
| `EA_Buf()` returns `false` when the buffer value is exactly `0.0`, so a legitimate zero is reported as "unavailable". | **Not a bug.** Ten call sites are engine reads (`EACommon.mqh` L138–147) that ignore the return value while the target variable was pre-set to `0.0` — a genuine `0.0` and a failed read are indistinguishable *and mean the same thing*. The only site that branches, `EA_TRIAD_SURVIVE.mq5:393`, assigns `adx = 0.0` on the false branch, which is exactly what a real `0.0` would produce, and the subsequent test (`adx > 16.0` rejects) is a low-volatility *gate open* test, so the fallback errs on the permitted side. |
| Automated division-by-zero sweep (30 candidate lines): tick-volume `median` in round4_contestant_a, `stopDist` in round5_contestant_b, `InpThrottleStepPct` in round11_contestant_d, `MathSqrt(va*vb)` in round10_claude_opus_5, legacy balance denominators. | **Not bugs.** MQL5 float division by zero yields ±inf/NaN without raising, and each candidate is either guarded (`median <= 0.0` returns first; `va <= 0 || vb <= 0` returns 0; `hwm <= 0` re-seeds; `stopDist <= 0` returns first), rejected downstream (`plan.riskDist <= 0` makes `EA_ExecutePlan` skip the entry; `poolR > InpRunnerTargetR` falls back to the fixed target), or degrades in the safe direction (a zero `InpThrottleStepPct` removes the throttle rather than compounding it). Legacy `g_initialBalance`/`g_startOfDayBalance` are assigned from a live account balance in `OnInit`. |
| Out-of-range rate-array access in any generated EA. | **None found.** An automated index/count sweep over every `EA_Rates` call site (all 65 EAs + the engine) confirmed the highest index read is always ≤ `start + count − 1`. |
| `start=1` sites still present after fix #16. | **Intentional** — see the "deliberately unchanged" list in #16; they are day/session windows iterated from index 0. |
| Dead inputs in the 13 legacy §1 EAs (27 declarations, e.g. `InpSymbolsToTrade`, `InpMagicNumber`, `InpMaxDrawdownPct`). | **Out of scope, pre-existing.** Those files predate the 65-EA delivery and are not generator output; they are recorded under "Known limitations" instead of being rewritten. |

## Known limitations (unchanged, not bugs)

* No MetaEditor in this environment: `.ex5` compilation and Strategy Tester runs
  still have to happen on Windows (tracker §4). The audit is static + logic review.
* The 12 legacy helper EAs and `EA_studyarena_round1_contestant_a.mq5` are
  self-contained MQL4-era files: they do not use the shared engine, carry
  `#property strict`, and one of them (`EA_master_combination_strategy.mq5`)
  still contains a `// Placeholder for actual calculation` line. They are outside
  the 65-EA delivery and were left functionally untouched (only the `Symbol()`
  compile error was repaired).
* Parameters that depend on the broker (commission per lot, spread, swap,
  session times, stop levels) are read at runtime; the values in the inputs are
  conservative defaults, not verified broker figures.
* The 13 legacy §1 EAs still declare 27 inputs that nothing reads (chiefly
  `InpSymbolsToTrade`, `InpMagicNumber`, `InpMaxDrawdownPct`, `InpBaseRiskPct`).
  Fixing that means rewriting self-contained files that are outside the 65-EA
  delivery; the new dead-input guard applies to the generator, so it cannot
  spread to the generated set.
