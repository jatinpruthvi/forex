# EA Bug Audit — 2026-10-02

Deep correctness audit of the implemented EA tree requested by the owner
("check in depth to make sure we do not have any bug").

Scope: `MQL5_Master/` — the shared engine (`Include/EACore.mqh`, `EASignals.mqh`,
`EATrade.mqh`, `EACommon.mqh`), the 65 strategy EAs generated by
`scripts/gen_additional_eas.py`, and the 13 legacy §1 EAs that live beside them.

Method: no MQL5 compiler exists in this environment, so the audit combined
(a) purpose-built static checkers (structure/braces, include resolution, symbol
resolution, `cfg/ctx/plan` field existence, call arity, duplicate definitions,
declared-before-use, dead config, magic uniqueness), (b) a line-by-line review of
the engine's hot path (entry gate, sizing, execution, exits, day/rollover
accounting), and (c) the repository's own contract checker
(`scripts/check_mql5_source.py`), which was extended so every defect class found
here is now caught automatically.

Every defect below was reproduced from the sources, fixed at the source of truth
(`scripts/gen_additional_eas.py` for generated EAs, the engine `.mqh` files for
the shared logic), regenerated, and re-verified.

## Defects found and fixed

| # | Severity | Where | Defect | Fix |
|---|---|---|---|---|
| 1 | **Critical (compile)** | all 65 generated EAs | `#include "..\Include\EACommon.mqh"` cannot resolve from `Experts/additionalEAs/`: MetaEditor looks in `Experts/Include/`, which does not exist. No generated EA could compile. | Emitted path is now `..\..\Include\EACommon.mqh` (correct from the `additionalEAs` folder, and from `Experts/` for `Master_Triad_V1`). Verified by the new include-resolution check. |
| 2 | **Critical (compile)** | 4 generated EAs (#16, #17, #18, #23) | `input double InpPhaseInitialBalance = 2500.0; // …` was emitted on the same physical line as the next `input` declaration, so the trailing `//` comment swallowed it → `InpSpreadMedianMult`, `InpCommissionPerLotRT`, `InpExtremeBodyAtr`, `InpGateDataProvenanceOK` were undeclared. | Newline restored in the generator; new checker rule "input declaration glued onto a comment". |
| 3 | **Critical (compile)** | `EA_THE5ERS_PROPOSAL_REVIEW.mq5` | `input double InpQualifyingDayCash` declared twice → redefinition error. | Duplicate removed; new checker rule "duplicate input declaration". |
| 4 | **Critical (compile)** | `EA_studyarena_round5_contestant_b.mq5` | `cfg.beOffsetR = 0.30;` — no such field in `SEASettings` → unknown member. | `breakEvenAtR/beOffsetR` added to `SEASettings`; the break-even move in `EA_ManagePositions` now honours the offset (`entry + dir * max(2 points, beOffsetR·R)`). New checker rule "unknown SEASettings field". |
| 5 | **Critical (compile)** | `EA_studyarena_round10_claude_fable_5_high_reasoning.mq5` | `SpreadGuard(ctx, plan)` called with 2 arguments; the method takes only `ctx`. | Call corrected. A call-arity checker now covers every generated EA. |
| 6 | **High (risk)** | shared engine, `EA_ExecutePlan` | When the risk budget implied less than the broker's minimum lot, `EA_NormalizeVolume` clamped *up* to the minimum → the position risked more than the configured tier, contradicting the documented "minimum lot unsafe → skip" rule. | Added an explicit pre-send check: if the minimum lot's all-in loss exceeds the budget, the entry is skipped and logged. |
| 7 | **High (accounting)** | shared engine, `ctx.dayRealizedPl` | The field that strategies use for "day locked / day P&L" actually returned realized **plus floating** P&L. | `ctx.dayRealizedPl` is now realized-only; the combined figure is exposed separately as `ctx.dayPl`. |
| 8 | **High (accounting)** | `EA_THE5ERS_CHALLENGE_V2_REVALIDATION.mq5`, `EA_THE5ERS_PROPOSAL_REVIEW.mq5` | Both EAs ran their own qualifying-day counter in addition to the engine's, writing the same `EA_<magic>_QualDays` global → double-counted qualifying days and a second, conflicting counter. | Inline counters removed; the engine is the single owner of the rule (`min(balance, equity)` delta vs the 0.5 % threshold) and the EAs log its value. |
| 9 | **High (compliance)** | 5ers family (#16–#23) | The daily anchor, day lock and request counters rolled on the **London clock day**, while the prop-firm docs lock firm rollover to the **broker server day** ("must not use … London time for firm rollover"). | New `cfg.dayAnchorServer` (wired `true` on #16–#23); `DayStart()`/`DayStartServer()` drive every day-scoped rule and history window. |
| 10 | **Medium (safety)** | shared engine, `CanOpen` | Hitting the daily request cap called `Halt()`, which (with the new `flattenOnHalt`) also liquidated open positions — but the docs say the cap blocks *new entries only* and must never suppress safety closes. | The cap now blocks new entries and logs; no halt, no flatten. |
| 11 | **Medium (safety)** | shared engine, `EA_ManagePositions` | After a restart/recompile, `riskDist` was re-derived from the *current* stop. If the stop had already been moved to break-even, every R-multiple exploded and partials/trailing fired immediately. Positions with an unknown risk also skipped the time stop. | Initial risk distance is persisted per ticket (`EA_<magic>_R<ticket>`) and restored on sync; the time stop now runs before the R-based guard. |
| 12 | **Medium (exits)** | shared engine, partial closes | A transient `PositionClosePartial` failure was indistinguishable from "cannot split" and marked the partial as permanently done. | New `CEAExecutor::CanPartial()`; a genuine failure now retries on the next tick. |
| 13 | **Medium (compile)** | 4 legacy §1 EAs | MQL4 `Symbol()` used in MQL5 code (`_Symbol` is the MQL5 form) → compile error. | Modernised (8 call sites); the checker now flags the MQL4 form while leaving `object.Symbol()` alone. |
| 14 | **High (repo)** | `MQL5_Master/Include/{EACore,EASignals,EATrade,EACommon}.mqh`, `scripts/gen_additional_eas.py`, `scripts/check_mql5_source.py` | The engine, the generator and the checker were **untracked in git** — a fresh clone of the branch contained 65 EAs that cannot compile and no way to regenerate them. | Added to version control in this commit. |
| 15 | **Low (docs/rules)** | `EA_THE5ERS_2_5K_CHALLENGE_PLAN.mq5` | `maxTradesPerDay` allowed 5 (the module's back-test frequency) while the plan's account rules say "at most two sequential trades and two losses per day". | Effective cap is now 2, with `dayLockAfterTrades = 2` and `dayLockAfterLosses = 2`; the doc conflict is noted in the tracker. |

## Known limitations (unchanged, not bugs)

* No MetaEditor in this environment: `.ex5` compilation and Strategy Tester runs
  still have to happen on Windows (tracker §4). The audit is static + logic review.
* The 12 legacy helper EAs and `EA_studyarena_round1_contestant_a.mq5` are
  self-contained MQL4-era files: they do not use the shared engine, carry
  `#property strict`, and one of them (`EA_master_combination_strategy.mq5`)
  still contains a `// Placeholder for actual calculation` line. They are outside
  the 65-EA delivery and were left functionally untouched (only the `Symbol()`
  compile error was repaired).
* Parameters that depend on the broker (commission per lot, spread, swap,
  session times, stop levels) are read at runtime; the values in the inputs are
  conservative defaults, not verified broker figures.
