The suite is organized as flat `unittest.TestCase` modules under `tests/`, each targeting a distinct contract surface:
- `triad_reference.py` is an independent, stdlib-only Python oracle implementing profile math, day-state transitions, firm floors, volume rounding, session bounds (London/New York with DST), halt-latch signatures, and UTC-to-server conversion; it has no dependency on MQL5 or the tools package.
- `test_reference.py` asserts the oracle's own invariants (profile cash, drawdown tiers, phase locking, profit calculation).
- `test_validation.py` validates the `tools.triad_validation` pipeline: registry integrity (committed JSON vs. `build_registry()`), 160-config matrix enumeration, fill policy application, bootstrap expectancy intervals, champion selection isolation from holdout data, and phase simulation reports.
- `test_extended_validation.py` covers the P0 extensions: account-wide router priority/cost/time tie-breaking, extended metric/phase reports, replay exporter coverage and CSV round-trip, split-cut enforcement, and self-test invocation.
- `test_ablation_scaffold.py` tests the preregistered ablation framework (`tools.triad_ablation`): registry schema/version/sha256, six runs with baseline first, per-variant entry-spec deltas, build/export coverage, paired-day differences, bootstrap intervals, CLI `build/validate/preregister` commands, and end-to-end evaluation scenarios.
- `test_bugfix_regressions.py` encodes specific defects found during review: breakeven cap pricing, net_r/net_cash agreement across all exit paths, stop-side guards, loader validation errors, decide robustness, R3 holdout fill floor, randomized invariants over 120 synthetic events, and stressed-cash consistency.
- `test_source_contract.py` and `test_screen_ea_contract.py` perform static source-contract checks on the canonical `TRIAD_R_HS.mq5` and the demo `TRIAD_SCREEN.mq5`: token presence/absence, default-gate values, symbol universe, session windows, challenge state machine, dashboard objects, risk guards, order submission defaults, and git-status assertions to ensure canonical files remain unmodified.
Dependency direction is one-way: test modules import `tools.*` and `triad_reference`; they never modify production code and rely on committed registries under `validation/` as ground truth.
