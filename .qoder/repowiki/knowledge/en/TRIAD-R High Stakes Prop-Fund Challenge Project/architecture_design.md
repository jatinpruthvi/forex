The repository is organized around four cooperating layers: (1) `MQL5/Experts` holds the production EA (`TRIAD_R_HS`) and its demo/screen variant (`TRIAD_SCREEN`) written in MQL5; (2) `tools/` provides standalone Python scripts that parse historical data, build signal events, export replay rows, run ablation studies, and perform multi-pair grid optimization against the frozen strategy geometry; (3) `tests/` runs a unified pytest suite that cross-checks both EAs and all tooling against a pure-Python reference implementation and committed registries; (4) `validation/` stores the frozen configuration registry, instrument specs, and large M5 OHLCV tick datasets consumed by tools and tests. Cross-child wiring is contract-driven: the frozen entry-geometry constants and `triad_v2_1_registry.json` are the shared boundary between the MQL5 EAs and the Python validation stack, so any EA change requires re-running the full pipeline to keep results valid. A top-level `progress.md` acts as the canonical handoff document tying research findings, optimizer results, and remaining tasks across all children.
