Flat collection of `unittest.TestCase` modules under `tests/` with one-way dependencies: test files import from `tools.*` (`triad_validation`, `triad_ablation`, `replay_export`) and from the stdlib-only `triad_reference.py` oracle, which implements profile math, day-state transitions, firm floors, volume rounding, London/New York session bounds (with DST via `zoneinfo`), halt-latch signatures, and UTC-to-server conversion. `test_reference.py` asserts invariants of that oracle; `test_validation.py` checks registry integrity (`load_registry` vs `build_registry`), the 160-config matrix enumeration, fill policy application, bootstrap expectancy intervals, champion selection isolation from holdout data, and phase simulation reports; `test_ablation_scaffold.py` validates the preregistered ablation framework schema, six runs with baseline first, per-variant entry-spec deltas, build/export coverage, paired-day differences, bootstrap intervals, CLI commands, and end-to-end evaluation scenarios; `test_bugfix_regressions.py` encodes specific defects (breakeven cap pricing, net_r/net_cash agreement across all exit paths, stop-side guards, loader validation errors, decide robustness, R3 holdout fill floor, randomized invariants over 120 synthetic events, stressed-cash consistency); `test_source_contract.py` and `test_screen_ea_contract.py` perform static source-contract checks on canonical `TRIAD_R_HS.mq5` and demo `TRIAD_SCREEN.mq5` by reading file text and asserting token presence/absence, default-gate values, symbol universe, session windows, challenge state machine, dashboard objects, risk guards, order submission defaults, and git-status assertions. Committed registries under `validation/triad_v2_1_registry.json` and `validation/triad_v2_2_ablation_registry.json` serve as ground truth.
