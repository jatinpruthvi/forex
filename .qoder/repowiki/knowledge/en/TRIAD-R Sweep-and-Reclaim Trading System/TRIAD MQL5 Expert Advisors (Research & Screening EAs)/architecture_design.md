The module contains two independent MQL5 Expert Advisors under `MQL5/Experts/`, plus a shared news-calendar sample CSV under `MQL5/Files/`.

- `TRIAD_R_HS/TRIAD_R_HS.mq5` is the canonical production EA. It defines session, phase, profile, pattern-side, and lifecycle enums; a multi-session runtime state (`SessionRuntime[3]`) for London and New York windows across EURUSD, GBPUSD, USDJPY; and a signal-candidate pipeline that computes ATR/range percentiles, sweep/reclaim detection, risk sizing, and order submission via `CTrade`. Safety is enforced through a fail-closed design: operator gates (`InpEnableOrderSubmission`, `InpValidationReleaseId`, multiple `*GatePassed` flags), account identity checks against expected server/login/currency/leverage, a global-variable-based instance lock with heartbeat fencing, a signed halt latch (`Halt`/`HaltReason`/`HaltSig`), and a persisted account-state journal (`Cfg`, `Identity`, `DayKey`, `WeekKey`, `StateSig`). State persistence uses terminal globals written atomically with a final `StateSig` commit marker so partial crashes fail closed on restart. Time handling is centralized in civil-time helpers (`LondonUtcOffsetSeconds`, `NewYorkUtcOffsetSeconds`, `LocalWallToUtc`, `ServerToUtc`, `BuildBoundsForCivilDate`) that compute session boundaries with DST-aware offsets.
- `TRIAD_SCREEN/TRIAD_SCREEN.mq5` is a separate research/screening EA that ports the same entry/risk logic but omits lifecycle locks, GV journals, and identity hashing. It persists lightweight per-combo CSV files (`S.csv` state, `D.csv` daily summary, `J.csv` audit log) keyed by login and combo label, and renders an on-chart dashboard showing challenge status, qualifying days, signals/fills/rejects, and a configuration fingerprint hash.
- Both EAs share the same news-calendar schema: a CSV of `utc_time,currency,impact,title` rows where only RED/HIGH events are loaded and a `COVERAGE` row declares verified coverage end time. The example file `triad_red_news.csv.example` documents the format.
- Dependency direction is one-way: both EAs depend only on `<Trade/Trade.mqh>` and standard MQL5 library functions; they do not include each other. The screen EA explicitly states it is NOT the canonical EA and exists solely for demo screening.
